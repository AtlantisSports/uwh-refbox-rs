# v0.4.3 Draft Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a **draft** v0.4.3 GitHub release covering everything merged to master since v0.4.2, by bumping the workspace version and pushing the `v0.4.3` tag.

**Architecture:** Two stages with a human merge gate between them. (1) A `chore(workspace)` PR bumps every crate's version 0.4.2→0.4.3 (mirroring the prior bump commit 5dda5b7d). (2) After it merges to master, push a `v0.4.3` tag — `release.yml` triggers on `v*.*.*` tags, builds all platform binaries, and auto-creates the GitHub release as a **draft** (`draft: true`, `generate_release_notes: true`).

**Tech Stack:** Rust workspace (Cargo), `just`, GitHub Actions (`release.yml`), `gh` CLI.

## Global Constraints

- Cut from current `origin/master` HEAD `4ee61db6` (contains #1333 beep-test display, #1344 CJK font fix, #1345 startup-font fix). Confirmed content.
- Mirror prior version-bump commit **5dda5b7d** exactly: edit `version = "0.4.2"` → `version = "0.4.3"` and refresh `Cargo.lock`. Files: `fonts`, `led-panel-sim`, `matrix-drawing`, `overlay`, `refbox`, `schedule-processor`, `uwh-common`, `wireless-modes`, `wireless-remote` Cargo.tomls + root `Cargo.lock`. (Prior bump did NOT touch `wireless-remote/Cargo.lock`; neither will we.)
- `wireless-remote` is the embedded firmware (separate workspace): edit its version **string only** — no `cargo` runs in that dir, no behavior change.
- Do NOT publish — the release stays a draft for human review + spare-Pi self-update test.
- Approval gates (ask the human each time): create branch, commit, push, open PR, **push the tag** (this triggers the public release build).
- Branch `chore/workspace/bump-version-0-4-3`; commit `chore(workspace): bump version to 0.4.3`; merge via the GitHub merge-queue button (direct merges blocked).

### Task 1: Version bump PR (0.4.2 → 0.4.3)

**Files (mirror commit 5dda5b7d):**
- Modify: `fonts/Cargo.toml`, `led-panel-sim/Cargo.toml`, `matrix-drawing/Cargo.toml`, `overlay/Cargo.toml`, `refbox/Cargo.toml`, `schedule-processor/Cargo.toml`, `uwh-common/Cargo.toml`, `wireless-modes/Cargo.toml`, `wireless-remote/Cargo.toml` — every `version = "0.4.2"` → `version = "0.4.3"` (18 occurrences total: own versions + internal path-dep `version =` refs)
- Modify: `Cargo.lock` (regenerated by `cargo check`)

- [ ] **Step 1: Create worktree + branch off origin/master**

Use `git worktree add .worktrees/chore-bump-0-4-3 -b chore/workspace/bump-version-0-4-3 origin/master` (after `git fetch origin master`). Work from the worktree path (its cwd).

- [ ] **Step 2: Bump all version strings**

```bash
sed -i 's/version = "0.4.2"/version = "0.4.3"/g' \
  fonts/Cargo.toml led-panel-sim/Cargo.toml matrix-drawing/Cargo.toml \
  overlay/Cargo.toml refbox/Cargo.toml schedule-processor/Cargo.toml \
  uwh-common/Cargo.toml wireless-modes/Cargo.toml wireless-remote/Cargo.toml
```
(Verified safe: all `version = "0.4.2"` occurrences are workspace crates; no third-party dep is pinned to that string.)

- [ ] **Step 3: Verify no 0.4.2 remains + refresh Cargo.lock**

```bash
grep -rn 'version = "0.4.2"' --include=Cargo.toml . | grep -v worktrees   # expect: no output
cargo check -p refbox 2>&1 | tail -3                                       # rewrites Cargo.lock workspace pins
git diff --stat
```
Expected: 9 Cargo.tomls changed; `Cargo.lock` shows the 8 main-workspace crate versions bumped to 0.4.3; `wireless-remote/Cargo.lock` NOT changed (matches 5dda5b7d).

- [ ] **Step 4: Full validation**

Run: `just check`
Expected: fmt, lint, tests, audit all clean (pure version bump — no behavior change).

- [ ] **Step 5: Commit (after human approval)**

```bash
git add fonts/Cargo.toml led-panel-sim/Cargo.toml matrix-drawing/Cargo.toml \
  overlay/Cargo.toml refbox/Cargo.toml schedule-processor/Cargo.toml \
  uwh-common/Cargo.toml wireless-modes/Cargo.toml wireless-remote/Cargo.toml Cargo.lock
git commit -m "chore(workspace): bump version to 0.4.3"
```

- [ ] **Step 6: Push + open PR (after approval), merge via queue**

Push branch, `gh pr create` with a plain-language body (what: routine version bump for the v0.4.3 release; why: the released binary must report 0.4.3 so the self-updater recognizes it; how to verify: `just check` green, version strings show 0.4.3). Human merges via "Merge when ready".

### Task 2: Tag v0.4.3 → draft release

**Prerequisite:** Task 1 PR merged to master.

- [ ] **Step 1: Fetch merged master + confirm version**

```bash
git fetch origin master
git show origin/master:refbox/Cargo.toml | grep -m1 '^version'   # expect: version = "0.4.3"
```

- [ ] **Step 2: Tag the merged master commit (after explicit approval — this triggers the public release build)**

```bash
git tag v0.4.3 origin/master
git push origin v0.4.3
```

- [ ] **Step 3: Watch the release workflow**

Run: `gh run watch` (or `gh run list --workflow=release.yml -L 1`)
Expected: build-windows / build-macos-arm / build-macos-x86 / build-rpi / upload-release all succeed (~tens of minutes).

- [ ] **Step 4: Confirm the draft exists with assets + notes**

```bash
gh release view v0.4.3 --json isDraft,assets,tagName \
  --jq '"draft=\(.isDraft) tag=\(.tagName) assets=\([.assets[].name])"'
```
Expected: `draft=true`, assets include `refbox.zip`, `refbox-aarch64-linux`, `refbox-aarch64-linux.sha256`.

- [ ] **Step 5: Review/refine draft notes (optional)**

Auto-generated notes list merged PRs since v0.4.2. If the "Full Changelog" compare link or notes need adjusting (see prior-release memory), edit via `gh release edit v0.4.3 --notes-file <file>` while it remains a draft. Leave it as a draft — do NOT publish.
